# helmi-api Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one Cloudflare Worker that serves Spotify, Strava, and GitHub + Bitbucket activity data to the portfolio. It replaces `strava-web-api-backend` and `spotify-web-api-backend`.

**Architecture:** A Hono app on Workers with one KV namespace (`HELMI_KV`). Spotify routes call Spotify live, behind a short in-memory cache. Strava and activity routes only read KV. A 30-minute cron fills KV within a per-run subrequest budget. Refresh tokens live in KV and rotate automatically. Admin-only OAuth pages re-authorize a provider in one click.

**Tech Stack:** Bun (package manager), Hono 4, Wrangler 4, TypeScript, Vitest (plain Node environment, tests call `app.request(path, init, env)`).

**Spec:** `docs/superpowers/specs/2026-10-19-porto-revamp-design.md` §3, §4, §6, §7 step 1 (in the `webporto` repo)

## Global Constraints

- Repo location: `C:\Users\helmi\helmi-api`, a new git repo with default branch `main`. Package manager is Bun, tests use Vitest.
- Workers Free plan limits: 50 subrequests and 10 ms CPU per invocation, cron included. Keep KV writes under 1,000/day, target under 300.
- Cron schedule `*/30 * * * *`. `CRON_SUBREQUEST_BUDGET` defaults to `40`.
- Spotify scopes, exactly: `user-read-playback-state user-read-currently-playing user-modify-playback-state user-read-recently-played`.
- Strava scope, exactly: `read,activity:read`. Never `activity:read_all`.
- Strava runs:
  - Only `sport_type` in `Run`, `TrailRun`, `VirtualRun`, with `visibility === "everyone"`.
  - Trim the polyline by 300 m at each end before storing.
- Bitbucket: store only date → count. Never store repo names in activity data, and never store commit messages anywhere.
- Day buckets use Asia/Jakarta time (UTC+7).
- Suggest song (`POST /spotify/queue`):
  - No rate limit, by Helmi's decision.
  - Validate `uri` against `^spotify:track:[A-Za-z0-9]{22}$`.
  - Require `Origin` to be in `ALLOWED_ORIGINS`.
- The worker has no endpoints for play, pause, skip, seek, or position.
- Response bodies for errors are `{ "error": "<code>" }`. Codes:
  - `invalid_uri`, `invalid_query`, `forbidden_origin`
  - `not_listening`, `upstream_error`, `reauth_required`
  - `no_data`, `unauthorized`, `bad_state`, `missing_scope`, `not_found`, `internal`
- Secrets never go in git. Local values go in `.dev.vars`. Production secrets are entered by Helmi with `wrangler secret put`.

## Review Focus

1. **Spotify plays a podcast episode, an ad, or a local file** (item null, non-track type, or empty `album.images`). Expected: now-playing reports `isPlaying: false, track: null` for non-tracks and `imageUrl: null` when images are empty, and never throws. Test is in Task 3.
2. **A Strava run has `distance: 0` or an empty `summary_polyline`** (manual entry, treadmill). Expected: `avgPaceSPerKm: 0`, `polyline: null`. Test is in Task 4.
3. **Search text has `&`, `/`, `#`, or non-ASCII characters** (`AC/DC & me`, `Hindia – Evaluasi`). Expected: the query is URL-encoded and not truncated. Test is in Task 3.
4. **Bitbucket commit author is in a different case or format** (`Helmi T <HELMI@Example.com>`). Expected: matched case-insensitively. Commits by other authors are ignored. Test is in Task 6.
5. **A commit lands near midnight UTC** (`2026-10-18T20:00:00Z`). Expected: it counts on Jakarta day `2026-10-19`. Test is in Task 6.

    - `ReauthRequiredError` → `setHealth(provider, "error", "reauth_required")`, then `503 { error: "reauth_required" }`
    - anything else → `500 { error: "internal" }`

### Task 6: Bitbucket commit scanner

**Files:**
- Create: `src/lib/dates.ts`, `src/lib/bitbucket.ts`
- Test: `test/dates.test.ts`, `test/bitbucket.test.ts`

**Interfaces:**
- Consumes: `Budget` (Task 4); `csv` (Task 1)
- Produces:
  - `jakartaDate(input: string | Date): string`. Returns `YYYY-MM-DD` at UTC+7.
  - `daysAgo(now: Date, n: number): Date`
  - `type RawCommit = { hash: string; date: string; author: { raw: string } }`
  - `type RepoCursor = { newestSeen: string | null; backfillNext: string | null; done: boolean }`
  - `countMyCommits(values: RawCommit[], authorEmails: string[], since: string, stopAfter: string | null, seen: Set<string>): { counts: Record<string, number>; hitBoundary: boolean; newest: string | null }`
    - Counts commits by matching authors with `date >= since` and (`stopAfter === null` or `date > stopAfter`).
    - `hitBoundary` is true once any commit has `date < since`, or `date <= stopAfter`.
    - Emails come from `/<([^>]+)>/` in `author.raw` and are compared lowercased.
    - Hashes already in `seen` are skipped.
  - `syncBitbucket(env: Env, budget: Budget, now: Date): Promise<{ changed: boolean }>`

KV used by `syncBitbucket`:
- `bb:repos`: `{ repos: string[]; fetchedAt: string }`. Refreshed every 24 h from `https://api.bitbucket.org/2.0/repositories/{ws}?q=updated_on>"<since date>"&pagelen=100&fields=next,values.full_name`, following `next`, one budget unit per page.
- `bb:state`: `{ cursors: Record<string, RepoCursor>; rr: number }`. Written once per run, and only if changed.
- `activity:bitbucket`: `{ data: Record<string, number>; updatedAt: string }`. Dates older than 365 days are pruned on write.

Run algorithm:
1. No-op when `BITBUCKET_WORKSPACES` is empty.
2. Auth header is `Basic base64(BITBUCKET_EMAIL:BITBUCKET_API_TOKEN)`.
3. Visit repos round-robin starting at `rr`, while `budget.take()` succeeds. Each repo visit is one page:
   - **Not done (backfill):** fetch `backfillNext`, or for a new cursor the first page `https://api.bitbucket.org/2.0/repositories/{full_name}/commits?pagelen=100&fields=next,values.hash,values.date,values.author.raw`.
     - Count with `stopAfter = null`.
     - On the first page, set `newestSeen` to the newest date.
     - `done = hitBoundary || !next`. Otherwise `backfillNext = next`.
   - **Done (incremental):** fetch the first page and count with `stopAfter = newestSeen`.
     - If `!hitBoundary && next`, keep following `next` on this repo while budget allows.
     - Set `newestSeen` to the max seen.
4. Set `rr` to the index after the last repo touched.
